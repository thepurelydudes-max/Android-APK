MLBB COUNTER ASSISTANT 2.0 — архитектура уровня WRCA
=====================================================

Основная идея
-------------
MLCA 2.0 использует ту же draft-first модель, что и текущий Wild Rift Counter Assistant:
- 60% — сила матчапов против всего введённого состава;
- 20% — покрытие: какую часть вражеского драфта герой реально контрит;
- 15% — актуальный Tier/meta-компонент;
- 5% — percentile винрейта героя на выбранной линии.

Роли строго разделены:
EXP / Лес / Мид / Голд / Роум.
Герой не должен предлагаться на чужую линию только потому, что хорошо контрит одного из пяти соперников.
Прямой lane-matchup имеет больший вес, но остальные четыре противника тоже участвуют в оценке.

Источники данных
----------------
1. Rone Arena API / RoneAI:
   - герои, роли и линии;
   - matchup/counter данные;
   - win/pick/ban;
   - предметы и изображения;
   - hero recommended content и полноценные сборки;
   - дополнительные build/counter данные.
2. MLBBDex:
   - каталог и метаданные;
   - актуальный Tier;
   - резервные hero/item данные.

Rone Arena API является неофициальным community-проектом.
Mobile Legends: Bang Bang и игровые материалы принадлежат Moonton.
MLCA не является официальным приложением Moonton.

База внутри APK
---------------
Перед Android-сборкой GitHub Actions запускает prepare_bundled_seed.py.
Он создаёт свежую локальную SQLite-базу и кэш, проверяет их и только после успешного аудита
позволяет собирать APK.

В APK вшиваются:
- assets/data/mobilelegends.db;
- русская локализация;
- портреты героев;
- иконки предметов;
- matchup matrix;
- role-specific builds;
- варианты сборок;
- ситуационные предметы;
- мета/Tier и статистика.

При чистой установке приложение копирует этот готовый снимок в writable storage.
Поэтому первый запуск не требует скачивания базы: рекомендации и изображения уже доступны офлайн.
Кнопка обновления нужна только для получения более свежего снимка данных.

Сборки предметов
----------------
Для выбранного героя и линии сначала используется его скачанный lane-specific core.
Первые три non-boot core-предмета защищены от случайной полной замены.
Обычно адаптируются последние два слота; при полном драфте из пяти соперников допускается до трёх
изменений только при наличии достаточного давления со стороны вражеского состава.
Ботинки рассматриваются как отдельный слот, и итоговая сборка никогда не должна содержать две пары.

Ситуативная логика учитывает:
- лечение / sustain;
- щиты;
- критический урон;
- скорость и базовые атаки;
- физический burst;
- магический burst / длительный магический урон;
- высокий HP и защиту;
- контроль;
- тип героя и совместимость контрпредмета с его обычным билдом.

Никакой предмет не должен добавляться только потому, что он абстрактно «контрит» врага:
сначала проверяется, допустим ли он для архетипа выбранного героя и не разрушает ли его core.

Надёжность обновления
---------------------
Перед упаковкой seed проверяется:
- PRAGMA quick_check SQLite;
- количество героев, предметов, матчапов и role-build;
- английские и русские имена;
- наличие и валидность портретов героев;
- наличие и валидность иконок предметов;
- build variants и role coverage.

Неполный seed не должен тихо попадать в APK: CI завершает сборку ошибкой.
При обычном обновлении сохраняются last-known-good данные, если внешний источник временно недоступен.
