Wild Rift Counter Assistant 3.5.0
====================================

Stability pass after 3.4.9.

Build fixes
-----------
- Final output now enforces exactly one finished boot.
- If a champion pool temporarily loses its boot row during refresh, the engine
  chooses a conservative finished boot fallback instead of returning a five-item build.
- Pure penetration/anti-tank items (Void Staff, armor-pen answers, etc.) are
  strongly situational and no longer treated as generic core.
- Support-role builds reject pure penetration leakage from a flex champion's
  shared Mid/Carry item pool.
- Current Build Trends item names are preserved during partial catalog refresh,
  preventing a parser hiccup from deleting a still-referenced finished item.

Icon fixes
----------
- Item icon_path is cleared whenever a newly verified icon_url changes.
- A new item-icon schema forces one complete item cache refresh.
- Forced refresh bypasses the same-patch/no-validator shortcut, so an old valid
  PNG cannot survive merely because its file is readable.
- The schema is marked complete only when all item images refresh without
  failed/stale-kept results.
- Existing 3.4.9 detail-page icon identity checks remain in place.

Root cause examples
-------------------
- Void Staff carried anti_magic_resist, but anti_magic_resist was absent from the
  core-situational tag set. That let it sort as ordinary Magic core.
- Boots had no final invariant: _core_build appended one only when a boot row was
  present in the refreshed pool. A partial refresh could therefore remove it.
- Some corrected icon URLs could still point at an old cached PNG because the
  cache considered the existing image reusable for the current patch.
