Wild Rift Counter Assistant 3.7.7
====================================

WildRiftCore build-data repair
------------------------------
Problem found in the 3.7.6 APK audit:
- role_builds: 0 rows
- role_build_situational: 0 rows
- role_build_boots: 0 rows
- build_page_cache: 0 rows
The app therefore fell back to WR Pocket item-pool synthesis for every champion,
which could create incoherent builds even when pick/counter data itself was valid.

Root cause
----------
WildRiftCore currently presents a Cloudflare managed challenge (HTTP 403) to
GitHub-hosted runners and to some Android/VPN routes. Browser User-Agent, curl
and headless Chrome do not solve the challenge.

3.7.7 source resilience
-----------------------
- Direct WildRiftCore remains the preferred source.
- When direct access fails, the updater uses Jina Reader for the same public
  WildRiftCore URL.
- Reader traffic is throttled below its published public rate limit.
- After the first direct WildRiftCore failure in one update run, later build
  pages go directly through the reader instead of repeatedly waiting on the
  already-blocked host.
- Build-page cache is patch-aware and schema-versioned.
- Partial failures never delete last-known-good role build rows.

Complete source model
---------------------
3.7.7 stores more than one standard five-item core:
- role_builds: WildRiftCore default champion+role core + boot
- role_build_variants: complete source variants such as Standard, Vs AD comps,
  Vs AP comps and champion-specific variants, including the source "When to
  pick it" trigger
- role_build_situational: role-local situational adaptations and exact
  opponent-to-item adaptations
- role_build_boots: source-approved boot alternatives
- build_page_cache: complete parsed source page payload by patch/champion

Recommendation order
--------------------
The item engine now:
1. Loads the exact WildRiftCore champion+role source build.
2. Selects one complete source variant only when the enemy draft has a strong
   composition-level signal; mixed drafts stay on Standard.
3. Applies at most the existing role-local/source-approved situational
   adaptations.
4. Uses WR Pocket fallback only when no healthy WildRiftCore role build exists.

Integrity guards
----------------
Manual update audits and reports:
- champions with no WildRiftCore role build
- role builds with no complete variants
- incomplete standard cores / missing boots
- incomplete variants
- referenced build items missing from the item catalog or image cache

APK build-time seed preparation is stricter:
- it refuses to package when WildRiftCore page coverage is incomplete
- it refuses to package champions with no WRC role build
- it refuses to package role builds without variants
- it refuses to package incomplete WRC build blocks
This prevents a green APK build from silently containing an empty WRC build
layer again.

Champion role repair
--------------------
A current WildRiftCore champion+role build is treated as strong lane evidence.
The updater merges those source-supported roles into champion lane metadata,
which helps newly released/flex champions when the structured roster feed lags.

Item identity/media
-------------------
- Variant item aliases are migrated together with standard role builds.
- Reader parsing preserves the visible WildRiftCore item label instead of
  inventing names from URL slugs.
- All items referenced by complete variants participate in catalog/icon
  integrity auditing.
