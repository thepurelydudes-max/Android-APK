Wild Rift Counter Assistant 3.6.9
====================================

Android DNS / network resilience
--------------------------------
- Real device log showed simultaneous NameResolutionError failures for WR Pocket,
  WildRiftCore and WildRiftCounter plus dozens of stale_kept media refreshes.
- Multiple unrelated hosts failing DNS in one update are now classified as one
  device/network DNS outage instead of independent parser failures.
- Generic HTTP requests retry short transient Android DNS/connection failures
  before giving up.
- WildRiftCore now retries transient RequestException failures with short waits;
  long waits remain reserved for explicit HTTP 429 rate limits.
- WildRiftCounter retains paced retries and now records DNS failures explicitly.

Cache preservation
------------------
- When a DNS outage is already detected, the updater stops media refresh network
  requests instead of issuing 100+ doomed portrait/item requests.
- Existing local portrait and item files are kept untouched.
- A pending forced item-icon schema migration is NOT marked complete while DNS
  is unavailable, so the repair retries on the next successful update.
- Champion stale_kept is treated as a valid cached portrait, not as one warning
  per champion.

Warnings
--------
- Source-level NameResolutionError messages and the skipped media refresh are
  collapsed into one actionable Network/DNS warning.
- The warning lists the failed hostnames and affected update subsystems.
- Previous database data remains intact when those sources cannot be resolved.

Regression coverage
-------------------
- Added tests for Android NameResolutionError recognition.
- Added tests that two unrelated DNS host failures trigger outage mode.
- Added tests that duplicated DNS/media warnings collapse to one entry.
