Wild Rift Counter Assistant 3.7.0
====================================

Android interface performance
-----------------------------
- Removed repeated filesystem path resolution/stat calls from the hot render path.
  Champion/item media locations are cached in memory until the runtime snapshot
  is refreshed.
- UI item lookup no longer opens SQLite while cards are being rendered; the
  already-loaded runtime snapshot is authoritative until the next data update.
- Recommendation results and all ten build previews are cached by selected role
  + enemy draft. Switching back to a previously viewed role reuses the exact same
  recommendation data instead of recalculating it.
- Enemy-role inference is cached inside the engine per runtime snapshot/draft.
  Previously the same up-to-120-permutation assignment could run once for picks
  and again for each of ten build previews.
- Normalized item-tag and finished-item lookups now use cached dictionaries
  instead of repeated linear scans.

Interaction rendering
---------------------
- Selecting a recommended champion no longer rebuilds all ten recommendation
  cards, matchup chips and item previews. Only the old/new selection indicator
  and the selected build panel are updated.
- Role changes still preserve the complete recommendation UI and logic; no
  recommendation feature was removed to gain speed.

Updater UI
----------
- Updater progress events are coalesced and painted at most about six times per
  second. Hundreds of page/image progress messages can no longer flood the Flet
  event loop and make role buttons or other controls feel several seconds late.
- The updater itself remains on a worker thread; this change only reduces Flutter
  repaint/message pressure.

Safety
------
- Runtime caches are cleared automatically after a database update so new
  champion/item images and recommendation data cannot remain stale.
- A backup of 3.6.9 was created before these performance changes:
  backup/wild-rift-3.6.9-before-ui-performance

Additional Android tree reduction
---------------------------------
- Removed the per-option portrait/control subtree from all five enemy dropdowns.
  With ~140 champions this removes roughly 700 nested avatar/image controls from
  the permanently mounted UI tree. The selected champion portrait beside each
  dropdown remains unchanged.
- Role-tab changes now use targeted control.update() calls for the five role
  buttons plus the pick/build columns instead of page.update(). Flutter no longer
  needs to traverse/diff every dropdown option when only the selected role and
  recommendations changed.
- Selecting a recommended champion likewise updates only the two affected cards
  and the build pane whenever those controls are mounted.
